# 子專案 3：手機版面（RWD 與觸控）設計

- 日期：2026-11-06
- 分支：`feat/android-support`（接續子專案 1、6、2）
- 路線圖：`docs/superpowers/specs/2026-11-05-android-support-roadmap-design.md`（子專案 3）
- 畫面草圖（本機、git-ignored）：`.superpowers/brainstorm/1943-1793926911/content/` 的 `mobile-nav.html`、`mobile-records.html`、`mobile-dialog.html`

## 一、目的

Android 版要讓手機使用者好用。做法**不是重新設計手機版**，而是：

1. **和桌面版一致**：頁面、導覽入口與順序、功能、欄位、排序與篩選規則都和桌面版相同，只依螢幕大小調整排版（RWD）。
2. **元件適合觸控**：每個互動元件都要在手指操作下好用，例如看圖元件要能雙指縮放、點兩下放大、長按出現選單。
3. **轉向也要好用**：手機直向、橫向都要考慮。

## 二、目標、非目標、反目標

**目標**
- 手機直向（最窄 360dp）與橫向（高度約 360dp）所有頁面與對話框都不溢出、不被截斷，主要資訊不用橫向捲動就看得到。
- 觸控目標至少 48dp。
- 只靠滑鼠才能用的操作（懸停說明、右鍵選單、滾輪縮放）在觸控下都有對應做法。
- 寬螢幕（桌面）時的畫面與行為和現在完全相同。

**非目標**
- 底部導覽列、重新安排頁面結構、新增功能。
- 檔案另存、分享、剪貼簿（子專案 4）；雲端同步登入（子專案 5）；上架（子專案 7）。
- 平板專屬版面（平板短邊 ≥ 600dp，沿用現有桌面版面）。

**反目標（就算能動也算失敗）**
- 手機上的內容或功能和桌面版不一致（少了欄位、少了入口、規則不同）。
- 寬螢幕時的桌面版行為被改變。
- 出現 RenderFlex overflow、文字被硬切掉（沒有省略號）、整頁要左右捲動。

## 三、做法（Approaches）

| 做法 | 內容 | 取捨 |
|---|---|---|
| **A. 共用判斷＋元件原地調整（採用）** | 一個小工具統一判斷「是否手機排版」，各元件在原地依它與可用寬度切換排版 | 只有一份程式、桌面路徑不動；每個元件要各自加窄版分支與測試 |
| B. 另寫一套手機頁面 | `MobileAppShell`、`MobileBannerPage` 等，依裝置選用 | 兩份程式容易不同步，違反「和桌面一致」 |
| C. 引入 RWD 套件 | 例如 `responsive_framework` | 專案已有自己的寬度分界，省下的程式不多卻多一個依賴；官方 `flutter_adaptive_scaffold` 已停止維護 |

使用者選 A。

## 四、判斷規則（使用者決定）

- **手機排版** ＝ 視窗**短邊 < 600dp**，不分作業系統。
  - 手機直向、橫向都是手機排版（短邊不隨轉向改變）。
  - Android 平板、展開的摺疊機（短邊 ≥ 600dp）用桌面排版。
  - Windows 視窗縮小到短邊 < 600 時也切成手機排版。使用者認為這是優點。
  - 注意：Windows 視窗最小尺寸是 800×450（`lib/services/window_state_keeper.dart` 的 `_kMinWindowSize`），寬度不會低於 800，所以 Windows 只會在**視窗高度 < 600** 時出現手機排版，看起來和「手機橫放」那一版相同（抽屜＋完整表格）。**不調整最小視窗尺寸**（待使用者確認，見第九節）。
- **內容排版**（表格或卡片列、一欄或多欄）依**當下可用寬度**決定，沿用各元件既有的 `LayoutBuilder` 分界（800、1024 等）；新增的分界只有記錄區（見 5.4）。
- 判斷集中在一個地方：在 `lib/theme/` 新增一個小工具（例如 `bool isCompactLayout(BuildContext context)`，以 `MediaQuery.sizeOf(context).shortestSide < 600` 計算；600 寫成具名常數）。所有元件都呼叫它，不在各處重寫 `MediaQuery` 判斷。
- 觸控改進（雙指縮放、點兩下、長按選單、往下滑關閉）**不看排版一律開啟**；滑鼠操作不會觸發它們，Windows 觸控螢幕也能受惠。
- **48dp 觸控目標規則只在手機排版套用**（設計者的決定）：寬螢幕時維持現有尺寸，避免改變桌面外觀（反目標）；Material 元件在 Android 本來就預設 48dp 觸控區，這條規則主要針對自製的小目標（rail／抽屜項目、狀態列連結、標籤 chip 等）。

## 五、各部分的決定

### 5.1 外殼（`lib/pages/app_shell.dart`）

**導覽**（使用者選定：收進抽屜）
- 手機排版時不顯示左側 rail，改用 `Scaffold.drawer`，AppBar 左上出現 ☰；也可以從螢幕左緣滑出。
- 抽屜內容和桌面 rail **相同**：總覽、「喚取」分隔、12 個卡池（同樣的圖示與短名）、分隔、貢獻者、設定；目前所在頁面要標示選中。抽屜用 rail 的「展開」樣式（圖示＋文字），項目高度至少 48dp。
- 點選項目後切換頁面並關閉抽屜。
- 桌面排版維持現在的 rail（展開、收合、極窄無標籤三種）完全不變。

**標題列**（使用者決定：元素全保留，空間不夠時 App 名稱先讓位）
- 手機排版時隱藏版本號；☰、App 圖示、App 名稱、帳號標示、更新按鈕全部保留。
- 空間不夠時的讓位順序：**App 名稱先縮**（省略號，必要時縮到完全不見）→ 帳號標示的**別名部分**再以省略號截短；UID、帳號標示的圖示、App 圖示、☰、更新按鈕不縮。任何寬度都不能 overflow（360dp 時名稱多半會消失，屬預期）。
- 帳號標示點開後的選單內容不變，可看到完整別名與 UID。
- 「更新資料」改成圓形圖示按鈕（同一個 `actionUpdate` 動作），長按顯示文字說明（tooltip）。

**底部狀態列**（使用者決定：直向、橫向都顯示）
- 手機排版時，最後更新時間單行加省略號，社群連結只顯示圖示（`TeamLinksBar` 若有文字部分則在窄寬度隱藏）。
- 手機排版時社群連結的觸控區放大到 48dp，狀態列高度隨之變成約 48dp（設計者的決定，見 4 的 48dp 規則）。

### 5.2 總覽與卡池頁

- 卡片與圖表已會依寬度改成一欄；手機排版時頁面外距從 `AppSpacing.l` 縮小一級（建造者決定確切值，以畫面不擁擠為準）。
- 逐一檢查 360dp 寬下所有標題列（例如 `PageHeader` ＋分享按鈕）、`PityCard`、`StatCard`、圖例、5★ 一覽不溢出。

### 5.3 時間軸、圖片分類列、5★ 一覽等元件

- 水平捲動的元件（`TimelineHorizontal`、`GalleryChipBar`）要能用手指直接滑動；現有的左右箭頭／漸層提示保留，觸控目標至少 48dp。
- **只靠懸停才看得到的資訊**要在觸控下看得到：Flutter 的 `Tooltip` 在觸控下預設是長按觸發，逐一確認每個 tooltip 長按都能出現；若該元件點一下沒有其他動作，改成點一下就顯示。
- 帳號管理的拖曳排序把手觸控區至少 48dp。

### 5.4 喚取記錄（`SortableTable`、`SearchFilterBar`）

- **記錄區可用寬度 < 600dp** 時改成「卡片列」，否則維持現在的 6 欄表格。手機橫向（寬度足夠）顯示完整表格。
- 卡片列每筆兩行，整列可點開物品詳情（和表格列行為相同），列高至少 48dp：
  - 第一行：物品圖示、名稱（省略號）、星級（依星級上色）。
  - 第二行：時間（含相對時間）、總抽序、保底內（保留桌面的好運／歹運顏色）。
  - 條紋背景、分頁器 `Pager` 照舊。
- 卡片列沒有欄位標題，排序改成篩選列上的「排序：<欄位> <方向>」按鈕，點了從底部滑出選單，列出和表格相同的 6 個欄位。點選某一欄的效果**等同點該欄的表格標題**（呼叫同一個 `cycleSort`：降冪 → 升冪 → 不排序），目前狀態要打勾並標示方向。
- 篩選列：搜尋欄獨佔一行，星級、類型、排序、清除排成可換行的一列（`Wrap`）。

### 5.5 對話框（`AppDialog`）

- 手機排版時，對話框四周只留 12dp（目前寬度左右各留 40dp、高度保留 120dp），讓內容更寬、更高。寬度上限 `size.maxWidth` 照舊。
- 按鈕列放不下時自動換行（`AlertDialog` 的按鈕列本身會換行，確認沒有被其他包裝擋掉）。
- 規則仍集中在 `AppDialog`，各對話框不自行計算尺寸（符合 CLAUDE.md）。

### 5.6 物品詳情對話框（`gacha_item_detail_dialog.dart`）

- 內容與桌面相同：圖示、名稱、簡介、標籤、立繪／造型切換列、在 encore 查看、關閉。
- 直向：只套 5.5 的 12dp 規則，立繪區自然變大。
- **對話框高度不夠時**（手機橫向）改成左右兩欄：左邊放圖示＋名稱、簡介（可捲動）、標籤、按鈕；右邊放切換列＋立繪。切換的高度門檻由建造者依實際內容決定，以「立繪可用高度不會小於約 200dp」為原則。

### 5.7 看圖元件（`zoomable_image_overlay.dart`）

- **雙指縮放**：開啟（目前 `scaleEnabled: false`），縮放範圍和現在相同（1～5 倍），拖曳平移照舊。
- **點兩下**（觸控）：在原尺寸 ↔ 2 倍之間切換，以點擊位置為中心。**滑鼠單擊縮放必須維持立即反應**，不能因為加了雙擊判斷而延遲。建議依點擊的 `PointerDeviceKind` 分流：滑鼠走現有單擊、觸控自行判斷連點兩下。
- **觸控點一下圖片沒有反應**（使用者決定）；點圖片外的背景仍然關閉。
- **長按圖片**：彈出和右鍵相同的選單（儲存圖片等）；右上角 ⋮ 選單照舊。
- **往下滑關閉**：未放大時往下拖超過門檻就關閉；放大時拖曳仍是平移。
- 手機排版時圖片四周留白從 48dp 縮成 8dp；點背景關閉保留。
- 轉向（viewport 尺寸改變）時縮放重設為原尺寸並置中，圖片不會卡在畫面外。
- 桌面行為（滾輪縮放、單擊縮放、右鍵選單、ESC、游標樣式）不變。

### 5.8 其他頁面

- 設定頁、貢獻者頁、讀取遊戲記錄設定頁：在手機直向與橫向尺寸逐區檢查，橫排放不下的按鈕改成可換行（`Wrap`），標籤與值的列不溢出。
- 更新進度對話框在子專案 2 已處理橫向，確認仍正常即可。

## 六、文字與語系

- 新字串只加在核心四份 ARB（`app_en.arb`、`app_zh.arb`、`app_zh_Hans.arb`、`app_ja.arb`），例如排序按鈕「排序：{column}」、排序選單標題、方向說明；欄位名稱沿用既有的 `tableTime` 等。
- 中文全形標點；省略號用 ASCII `...`。

## 七、限制（CLAUDE.md 與專案慣例）

- 對話框一律 `AppDialog`；所有宣告寫一行 `///` dartdoc；新增 log 用英文並沿用 Logger 命名樹。
- 不新增 RWD 相關依賴。
- 指令一律 `fvm flutter` / `fvm dart`；提交前 format、analyze（`No issues found!`）、test（`All tests passed!`）。
- Riverpod 3；不要動 `rust_builder/`。

## 八、驗證

- **Widget 測試**：每個改到的元件或頁面，都在手機直向 360×800、手機橫向 800×360 下確認沒有 overflow 例外（`tester.takeException()` 為 null）且行為正確；外殼與記錄區另外在 1280×800 確認桌面版面不變（仍是 rail、仍是表格）。
- 關鍵行為各自有測試：抽屜項目與選中狀態、點項目後關閉抽屜；卡片列與表格的切換門檻；排序選單呼叫 `cycleSort` 並正確顯示狀態；`AppDialog` 在手機排版的邊距；看圖元件的雙指縮放、觸控點兩下、滑鼠單擊仍立即縮放、長按選單、往下滑關閉。
- **實機**：ASUS ROG Phone（1080×2400）直向與橫向逐頁檢查，包含轉向時正在看圖、對話框開著的情況。
- **Windows**：把視窗高度縮到 600 以下確認切成手機排版且可用，拉回後恢復桌面版面。

## 九、已確認事項與留給建造者的部分

**使用者已確認**
- Windows 最小視窗尺寸維持 800×450（Windows 只會出現「橫向手機」那一版）。
- 觸控點一下圖片沒有反應；標題列空間不夠時 App 名稱先讓位。

**設計者的決定（可在核准時推翻）**
- 48dp 觸控目標只在手機排版套用；狀態列在手機排版變成約 48dp 高。

**留給建造者**
- 對話框 12dp 邊距的實作方式（例如 `AlertDialog.insetPadding`）。
- 詳情對話框兩欄版的確切切換門檻；按鈕放在左欄。
- 未排序時排序按鈕的文字（例如「排序：預設」）。
- 往下滑關閉與平移的手勢區分方式（未放大時才判斷關閉）。
- 手機排版的頁面外距確切值。
