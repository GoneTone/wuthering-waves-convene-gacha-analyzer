# Android 版底部橫幅廣告設計

日期：2026-11-09
狀態：待使用者核准（審閱意見已併入）

## 目的

Play 上架的 Android 版加入廣告，讓專案**多少有一點收入**。底線是**不能打擾使用者**：不要任何需要強制觀看的廣告（插頁、要看完才能用功能的獎勵廣告），也不追求收入最大化。

## 目標

- Android 版在有內容的頁面底部顯示一則 AdMob 自適應橫幅（anchored adaptive banner）。
- 符合 AdMob 政策與 Google Play 政策，不因廣告被停權或下架。
- 歐盟／英國等需要同意的地區，依 Google 要求取得廣告同意。
- 隱私權政策、Play 資料安全表單、廣告聲明同步更新，內容與實際行為一致。

## 非目標

- Windows 版不放廣告（官方套件也不支援 Windows）。
- 不做插頁、獎勵、原生廣告；不做「看廣告支持開發者」按鈕。
- 不做付費移除廣告、不做贊助入口（之後若要再另外討論）。

## 反目標（做到了也算失敗）

- 廣告擋住或緊貼任何可以點的東西，造成誤觸。
- 廣告出現在沒有內容的畫面（違反 AdMob 政策，可能被停權）。
- 開發或測試時載入正式廣告（自己點到會被判無效流量）。
- 廣告讓頁面跑版、溢出，或在手機橫向時把內容擠到不能用。

## 限制（依官方政策原文，2026-11-09 查證）

- **橫幅位置**（AdMob 6275345、6275335）：不可緊鄰互動元素與 App 內容；放在底部時要有「邊框或足夠的間隔」；建議保留固定空間，App 內容不能出現在那塊空間裡；不可浮在內容上、不可隨捲動移動。
- **內容比例**（Google 發布商政策 9335564）：不允許在「沒有發布商內容或內容價值低」的畫面放廣告，也不允許廣告多於內容。
- **不可緊鄰操作按鈕**（9335564）：不可覆蓋或緊鄰導覽與其他操作項目。
- **不可誘導**：任何地方都不可出現「點廣告／看廣告支持我們」之類的文字。

## 考慮過的做法

| 做法 | 取捨 | 結果 |
|---|---|---|
| A. 底部固定橫幅 | 收入最穩、不擋操作、實作最單純；代價是常駐佔一條高度 | **採用** |
| B. 內容中的原生廣告卡 | 政策允許，官方有現成模板（小型最小 320×90dp）；但與 A 同畫面時廣告比例偏高，和「不打擾」衝突 | 不做，上線後看收入再評估 |
| C. 設定頁「看一則廣告」按鈕 | 不打擾，但「看廣告支持開發者」幾乎就是 AdMob 獎勵廣告政策（7313578）舉的違規例子；沒有獎勵也不適合用獎勵廣告；收入接近零 | 不做 |

使用者選 A，理由是收入與打擾程度的平衡最好，且政策最明確。

## 已決定的設計

### 平台

- 只在 Android 載入與顯示。Windows 與其他平台一律不呼叫廣告 SDK。

### 放在哪些頁面

- **App 外框裡的所有頁面**：綜合、各卡池頁、設定、貢獻者。（使用者決定）
- **不放**：
  - 「讀取遊戲記錄」設定流程（`LogAccessSetupPage`，另開的全螢幕引導頁）：主要按鈕在畫面下方，橫幅會緊鄰按鈕。（我的判斷）
  - 所有對話框：蓋在頁面上，不另外放廣告。
  - **沒有內容的畫面**：
    - 綜合頁：目前帳號沒有任何喚取紀錄時（顯示空狀態）。
    - 卡池頁：該卡池沒有紀錄、顯示「此卡池無紀錄」時。
    - 綜合頁與卡池頁在啟動載入中（`isBootstrapping`）、或尚未同步（`activeData == null`，顯示 `noSyncPageBody`）時，比照空狀態不放。（我的判斷）
    - 設定頁與貢獻者頁一律有內容，照常顯示（貢獻者名單是 `lib/data/contributors.dart` 的靜態資料，不會是空的）。

### 位置與外觀

- **手機直向**：固定在底部狀態列（「尚未同步」那一列，`shell-bottom-bar`）**上方**，兩者之間加分隔線。手機直向的狀態列只有文字，沒有可點元素。
- **平板等非手機排版**：底部狀態列右側有一排團隊連結按鈕（`TeamLinksBar`，`IconButton`），橫幅不能緊貼它們。所以橫幅只放在內容欄（不延伸到側欄下方），與底部狀態列之間保留至少 `AppSpacing.l` 的間隔加分隔線。（我的判斷，依 AdMob 6275335「在廣告與可點元素之間留緩衝」）
- **手機橫向**：外框本來就不顯示底部狀態列，所以橫幅固定在內容區最底部。橫向也要顯示。（使用者決定）
- 橫幅所在那一列是**固定空間**，頁面內容只在它上方捲動，不會捲到廣告後面。
- 橫幅與上方內容之間要有分隔線或間隔；橫幅緊鄰的位置不能有按鈕或其他可點元素。
- 尺寸：AdMob 自適應橫幅，寬度取可用寬度，高度由 SDK 依寬度決定。
- **載入失敗、沒有網路、尚未取得同意時**：不顯示，也不保留空白，那一列直接收起。（我的判斷）
- 手機排版開著鍵盤時，比照底部狀態列一起收起。（我的判斷）
- SnackBar（例如 Play 更新提示）出現時要浮在橫幅上方，不可蓋住廣告。（我的判斷）
- 進行中的流程不受廣告影響：更新資料、等待喚取等都是對話框，蓋在頁面上，橫幅照常留在底部，不另外處理。

### 廣告 ID 與測試

- 使用者已有 AdMob 帳號，實作時由使用者在 AdMob 建立這個 App，提供「應用程式 ID」與「橫幅廣告單元 ID」。
- **不寫進原始碼**（使用者提出）：專案是開源的，寫死的話任何人自己編譯都會用使用者的帳號播正式廣告，測試時的點擊會算成使用者帳號的無效流量，可能被扣款或停權。改比照雲端同步憑證的做法，**建置時注入**：
  - 本機：放在不進版控的 `secrets/ads_defines.json`，用 `--dart-define-from-file` 帶入；
  - CI：從 GitHub Actions secrets 讀取；
  - 應用程式 ID 必須寫在 `AndroidManifest.xml`（缺少時 SDK 啟動即閃退），由 Gradle 在建置時以 manifest placeholder 注入；
  - **沒有提供時一律使用 AdMob 官方測試 ID**（含測試應用程式 ID），只會出現測試廣告，不會閃退。
- 開發者自己的手機也要在 AdMob 註冊為測試裝置，避免用 Play 版測試時點到正式廣告。

### 年齡與廣告尺度（使用者確認）

- Play「目標對象」填 **13 歲以上**，不包含兒童，所以不走 Families 政策。
- 程式裡的 `RequestConfiguration` 把 `maxAdContentRating` 設為 **T（青少年）**。
- AdMob 後台封鎖**博弈、賭博**等敏感類別（抽卡工具配賭博廣告觀感很差）；這是後台設定，不在程式裡。

### 同意（歐盟／英國等地區）

- 使用 Google 的 UMP（User Messaging Platform）SDK，在需要的地區於 App 啟動後先取得同意，再請求廣告。
- 以 UMP 的 `canRequestAds()` 為準：使用者表態後（包括拒絕個人化廣告）就可以請求廣告，Google 會改投非個人化／有限廣告；尚未表態時不請求。這是 Google 設計的標準做法，不另外解析 TCF 同意字串。（我的判斷）
- AdMob 後台「隱私權與訊息」同時啟用**歐盟（GDPR）**與**美國各州隱私法規**的訊息（使用者確認）；隱私權政策要涵蓋這兩種的退出方式。
- 依 Google 要求，需要同意的地區要在設定頁提供「隱私權選項」入口，讓使用者之後能修改選擇；不需要的地區不顯示。

### 文件與 Play 聲明

- 隱私權政策（`docs/privacy-policy.md`，中英）新增廣告段落：使用 Google AdMob、會收集哪些資料、同意與退出的方式。
- Play Console：「廣告」聲明改為「含廣告」；「資料安全性」依 Google 官方公布的 Google Mobile Ads SDK 資料揭露內容補上廣告收集的類型（實作時以 Google 官方說明為準，不憑記憶填）；`AD_ID` 權限的用途聲明。
- 本機草稿 `private/play-store/data-safety.md` 同步更新；商店說明 `private/play-store/listing.md` 四種語言都寫了「沒有廣告，沒有分析追蹤」，要改掉。
- 移植筆記新增一節記錄廣告的決定與坑。
- **app-ads.txt**：`https://reh.tw/app-ads.txt` 已存在（使用者的網域，內容為 `google.com, pub-3794226192931198, DIRECT, f08c47fec0942fa0`），不需要改。Play 商店頁的「開發人員網站」要填 `https://reh.tw`，AdMob 才能比對到。（使用者確認）

## 留給實作者決定

- `google_mobile_ads` 與 UMP 的套件版本（依專案 Flutter 版本選相容的穩定版）。
- 「是否為 release 建置」與「頁面目前是否有內容」的判斷方式；最好沿用外框現有的路由與 `gachaRepository` 狀態，不要每頁各自實作。
- 橫幅 widget 的放置位置（建議在 `app_shell.dart` 統一處理，各頁不需要知道廣告存在）。
- log：廣告載入成功／失敗、同意狀態變化都要記 `Logger('ads')`，內容用英文、帶錯誤碼。
- 版面測試：手機直向、手機橫向、電腦寬度各一，確認有廣告位時不溢出、空白頁沒有廣告位、非 Android 完全不出現。
